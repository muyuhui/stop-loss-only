## ADDED Requirements

### Requirement: 遵循服务端声明的运行时能力
前端 SHALL 在应用启动期间加载运行时能力契约，并将其作为可选导航、仪表盘区域、路由行为和 API 轮询的判断依据。能力发现失败时，可选能力 MUST 默认关闭，同时受支持的核心流程仍应可以恢复。

#### Scenario: 旧版运行时不支持规划器
- **WHEN** 运行时能力表明风险规划不可用
- **THEN** 稳定导航不展示规划器，仪表盘不轮询风险预算接口，并通过明确说明展示不可用状态，不产生通用失败提示

#### Scenario: 能力不可用时直接访问规划器
- **WHEN** 用户直接打开 `/planner`，但风险规划不可用
- **THEN** 路由展示稳定的不可用状态和返回受支持页面的操作，并且不发起风险预览或仓位写入

#### Scenario: 能力发现失败
- **WHEN** 能力请求失败，但旧版核心页面仍可加载
- **THEN** 可选命令保持隐藏或禁用，页面保留核心数据，并向用户展示可恢复的能力状态说明

### Requirement: 区分预期不可用和请求故障
前端 API 层 SHALL 允许调用方标记预期内的能力拒绝，使业务状态可以局部呈现，而不触发全局通用错误提示。意外的网络、校验、数据库和行情源故障 SHALL 继续提供可操作反馈。

#### Scenario: 预期内的能力冲突
- **WHEN** 一个已明确受守卫保护的可选请求返回稳定的能力不可用错误
- **THEN** 所属视图记录不可用原因，且不出现全局“请求失败”提示

#### Scenario: 意外的仪表盘故障
- **WHEN** 受支持的仪表盘请求意外失败
- **THEN** 全局或页面级错误仍然可见，同时保留上一次成功的仪表盘数据
