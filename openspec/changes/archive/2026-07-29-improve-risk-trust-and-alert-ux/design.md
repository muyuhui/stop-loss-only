## Context（背景）

受支持的应用运行在 `legacy` 或 `shadow-read` 权限阶段，并将 `Holding` 视为唯一可写的组合事实。现有展示 DTO 会把依赖行情但缺失的百分比转换为 `0.0`，监控覆盖率辅助函数会把空分母转换为 `100.0`，若干前端工具还会通过 `Number(null)` 把 `null` 再次强制转换为零。告警页面也复用了面向 Position 的筛选条件，但 legacy 告警 API 无法执行这些条件；同时，未处置的 legacy 告警通常具有空处置状态。运行时能力发现已经存在，但仪表盘和设置页仍会渲染大块不可用的风险规划区域。

后端和前端作为本地单用户应用一同分发和启动，因此可以协调更新响应契约。已有告警记录和风险设置必须保持可读，不能采用破坏性数据迁移。

## Goals / Non-Goals（目标与非目标）

**目标：**

- 在存储展示、API 校验、格式化、排序和风险摘要的完整链路中，将依赖行情的未知值始终保留为未知。
- 明确区分零分母的不可用监控覆盖率与实际测得的 0% 覆盖率。
- 只提供稳定版 legacy 告警快照能够跨分页正确支持的筛选条件。
- 保持告警阅读状态相互独立，同时让处置状态与已经提交的 legacy 手动关闭事实同步。
- 从日常仪表盘和设置流程中移除因能力不可用而无法使用的风险规划区域。
- 使用确定性的 API、组件和浏览器测试保护上述行为。

**非目标：**

- 切换到 `new-authoritative`、启用 Position 生命周期写入或改变影子投影的权限归属。
- 新增需要告警快照表新字段的日期、资产类型、生命周期或风险状态筛选。
- 启用 CSV、Webhook 投递、浏览器系统通知权限、留存控制或券商集成。
- 修改止损公式、行情可操作性规则、历史图表语义或备份格式。
- 在本次变更中把所有 legacy 金额响应都转换为 Decimal 字符串。

## Decisions（决策）

### 使用可空派生指标，不使用哨兵数字

`HoldingResponse.profit_loss_pct` 和 `stop_loss_distance_pct` 将允许 `null`。没有可展示的估值行情时，legacy 展示适配器返回 `null`；对于保留的实时、延迟、收盘、净值或陈旧估值行情，仍继续计算百分比。前端共享格式化和风险辅助函数会先检查空值，再做数值转换；未知止损距离排在已知且未触发风险之后，也不计入“临近止损”数量。

拒绝“返回零并附加标记”的方案，因为每个调用方仍需记得该数字无效，一旦漏检就会显示不安全的零值。也拒绝字符串哨兵，因为它会削弱强类型 API 契约。

### 明确覆盖率的分母语义

没有活动持仓时，监控覆盖率辅助函数返回 `null`。存在活动持仓但覆盖数为零时，仍返回实际测得的 `0.0`。兼容字段 `quote_coverage_pct` 与可操作覆盖率保持一致，包括其可空性。仪表盘使用紧凑的“暂无活动持仓”或不可用标签，不会给缺失值附加百分号。

拒绝把空集合视为 100%，因为界面将该值作为行情可信度证据，而不是纯数学意义上的空真命题。

### 用稳定的 legacy 查询契约替换面向 Position 的告警控件

`GET /api/alerts` 将支持经过校验的 `search`、`unread`、`disposition`、`page` 和 `size` 参数。搜索在分页前匹配不可变的告警快照名称/代码。`unread=false` 明确选择已读告警。稳定排序继续按创建时间和 ID 倒序，因此前端移除排序、生命周期和风险控件，不再提供无法兑现的选项。

新建 legacy 触发告警会写入 `triggered` 处置状态。对于历史记录，载荷和触发筛选都把空处置状态规范化为 `triggered`。手动关闭 legacy 持仓时，在同一数据库事务中将相关待处理告警的处置状态更新为 `closed`。这样无需模式迁移或批量数据迁移，也能让新旧数据保持一致行为。

拒绝给告警表补充面向 Position 的缺失字段，因为这些概念超出稳定权限边界，也会不必要地扩大本次可用性变更的范围。

### 在区域边界按能力控制可见性

仅当 `risk_budget_reads` 为 true 时才渲染仪表盘风险预算区域。仅当风险预算读取或风险规划可用时才渲染设置页风险政策区域；只保存监控设置时不提交隐藏的风险字段，使已有值保持不变。规划器导航继续受能力保护；直接访问 `/planner` 时仍保留明确的默认关闭状态。

拒绝在正常流程中保留已禁用的说明卡片，因为它们会占用移动端高优先级空间，却无法提供可执行操作。也不移除受保护路由，因为书签和显式诊断仍需要稳定入口。

### 在各自归属边界测试契约

后端测试将断言可空 DTO/OpenAPI 行为、零分母覆盖率、服务端告警筛选、历史空处置状态兼容性，以及关闭操作与处置状态的原子提交。真实组件测试验证未知状态标签、URL 驱动的筛选、无效控件的移除和按能力隐藏的区域。现有三个视口的端到端流程增加断言，确保稳定页面不暴露能力关闭的风险区域，且移动端布局不受遮挡。

## Risks / Trade-offs（风险与取舍）

- [旧客户端可能假定百分比字段始终为数字] -> 将本变更作为本地 API/UI 协调发布，更新冻结样例和 OpenAPI 断言，并记录可空契约。
- [已有空告警处置状态可能产生意外的筛选总数] -> 在查询条件和响应载荷中一致地把空值规范化为 `triggered`，直至所有相关记录被关闭或重建。
- [隐藏风险设置会阻止在 legacy 模式下预先配置] -> 保留后端已有值；运行时声明可用风险流程后，控件自动重新显示。
- [未知持仓可能在视觉上被过度弱化] -> 保留现有行情可信度文字，并显示明确的“风险未知”标签，而不是留空。
- [服务端搜索在超大 SQLite 数据集上可能较慢] -> 限制查询长度并保持稳定分页；预期本地数据量无需索引，后续可根据实际证据重新评估。

## Migration Plan（迁移计划）

1. 更新后端 DTO、展示语义、监控覆盖率和告警查询/处置行为，并补充集成测试。
2. 更新前端空值处理、告警筛选、能力控制区域和组件测试。
3. 更新冻结 API/OpenAPI 样例，并扩充三个视口的浏览器断言。
4. 连续两次运行完整离线验证命令，并严格校验本 change。

不需要数据库模式迁移。回滚方式是恢复协调发布前的应用版本；已有告警处置值和已保存风险设置仍与旧版代码兼容。
