## Why

仓库当前同时暴露 legacy 持仓工作流、尚未完整集成的 Position 领域切换以及平台扩展。执行 `new-authoritative` 切换后，监控、历史、前端写入、导入和通知可能分别使用不同事实源，而现有质量门禁既未覆盖该状态，也未验证主规格。

本 change 要在继续扩展平台前建立一个真实且默认拒绝的受支持运行面：legacy `Holding` 模型继续作为权威事实源，未完成的 Position 与扩展能力被隔离，核心 HTTP 与导航回归得到修复，并由验证命令在干净环境中证明受支持用户流程可用。

## What Changes

- 将 legacy 持仓运行模式定义为本版本唯一受支持的权威模式，并让 Position 切换命令拒绝跨越尚未支持的边界。
- 保留 shadow 投影和对账作为诊断能力，但不得把 Position 领域写操作呈现为稳定用户流程。
- **破坏性变更**：在相关 worker 和权威模型集成完成前，暂时从稳定 UI 与公共运维接口中停用 CSV 仓位导入导出、Webhook 投递配置、浏览器系统通知启用和保留策略控制。
- 将告警操作指向受支持的持仓详情工作流，并移除或隔离孤立的 Position UI 路径。
- 保留刷新和设置操作预期的 `409`、`422` 与 `503`，不得统一转换为通用 `500`；全量与限定范围刷新必须一致返回稳定错误码。
- 在本稳定版本中，让仪表盘、持仓、价格历史、监控诊断和可见设置统一使用 legacy 权威模型。
- 用真实组件测试和浏览器测试替代源码文本检查与仅 API smoke 的 E2E 声明，在三个目标视口覆盖创建、刷新、触发、查看告警和关闭流程。
- 让仓库验证命令使用隔离临时状态，检查完整依赖，验证全部当前 OpenSpec 规格，并在路由、构建、浏览器或契约回归时失败。
- 使主规格和文档与受支持运行面保持一致，同时保留归档 change 作为历史记录，并将推迟的平台工作保留在路线图中。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `local-operations`：定义本版本受支持的权威边界、默认拒绝的切换行为、依赖预检和恢复验证。
- `holdings-crud`：让稳定用户流程继续使用 legacy 持仓，并推迟仅 Position 支持的创建、批次、部分平仓、确认和重新布防流程。
- `dashboard`：要求仪表盘事实与导航一致使用受支持权威模型。
- `price-fetching`：统一全量和限定范围刷新错误契约，并防止刷新跨越权威模型。
- `alert-system`：将告警查看与处置入口指向受支持权威模式下可达的工作流。
- `data-portability`：在导入导出会产生不可见或不可监控记录期间停用该能力。
- `notification-delivery`：在存在有效投递 owner 前，从稳定运行面移除未完成的外部通知和浏览器系统通知控制。
- `runtime-settings`：稳定设置只保留能在受支持运行时中真正应用和观察的控制项。
- `frontend-shell`：要求每个可见导航与命令都指向受支持路由，并使用一致中文界面文案。
- `quality-gates`：使用真实组件、目标浏览器视口、干净依赖状态和全部当前 OpenSpec 规格验证完整受支持流程。

## Impact

- 后端：权威模式管理、持仓/Position/价格/监控/运维/设置路由、刷新错误处理、调度器所有权以及请求响应模型。
- 前端：路由、告警、设置、孤立 Position 资源、本地化文案、API 错误处理和关键流程测试。
- 工具链：`setup.ps1`、`start.ps1`、`verify.ps1`、离线 smoke、浏览器测试工具和 OpenSpec 校验范围。
- 规格：上述十个修改的 capability，以及被推迟的 Position 切换和本地平台扩展文档。
- 不删除任何数据库表，不修改归档 OpenSpec 产物；shadow 数据可以继续重建，为未来迁移保留基础。
