## Why

现有系统能够可靠计算持仓止损、行情可信度和风险容量，但用户仍需自行把近期行情、持仓状态与组合风险拼接成可理解的复盘结论。增加一个受严格事实边界约束的 DeepSeek 持仓复盘能力，可以帮助用户更快识别应优先处理、暂停加仓或补齐数据的持仓，同时不把大模型包装成价格预测器或交易执行器。

## What Changes

- 在 legacy 与 shadow-read 稳定运行面为活动 Holding 提供按需、只读的 DeepSeek 单持仓复盘。
- 复盘前按用户明确操作刷新目标持仓当前行情，并补齐独立于买入日期的最近 90 个自然日日线或基金净值；数据不足或刷新失败时按可信度规则降级或拒绝分析。
- 后端使用确定性计算生成持仓、止损、近期行情指标和组合风险摘要，再将受限事实快照发送给 DeepSeek；金额、收益、回撤、波动和风险占用不得交由模型自行计算。
- DeepSeek 返回经过结构校验的中文复盘，包括复盘结论、受限建议动作、事实依据、风险情景、数据局限、可信程度和生成时间。
- AI 分析本身不修改 Holding、Position、止损、告警、设置或订单事实，不自动下单，也不得覆盖已触发止损、行情可信度或风险覆盖等确定性结论；用户明确触发的前置行情刷新仍按现有监控规则更新行情事实与告警，分析窗口可以补齐 `price_history` 技术缓存。
- 设置页支持配置、替换、清除和检测 DeepSeek API Key；密钥只使用本机加密存储，不进入 SQLite、日志、诊断包或备份。
- 第一版只实现 DeepSeek，但通过内部 Provider 契约隔离模型调用、错误映射和结构化响应，后续供应商扩展不改变复盘 API 与前端结果契约。
- 为 AI 能力增加独立运行时能力字段，并在未配置、超时、限流、响应无效或网络不可用时提供稳定、可恢复的降级状态。

## Capabilities

### New Capabilities

- `ai-holding-reviews`: 定义近期行情准备、确定性复盘快照、DeepSeek 结构化分析、建议边界、失败降级、隐私保护和只读保证。

### Modified Capabilities

- `runtime-settings`: 增加 DeepSeek API Key 的本机安全配置、状态展示、替换、清除和连接检测行为。
- `runtime-capabilities`: 增加不包含密钥或持仓信息的 AI 持仓复盘能力声明，并使前端入口与直接 API 守卫共享同一策略。
- `quality-gates`: 增加完全离线的 Provider fixture、结构校验、零写入、隐私日志、真实组件和三个目标视口复盘流程门禁。

## Impact

- 后端将新增 AI 复盘路由、行情快照与指标服务、Provider 抽象、DeepSeek 适配器、结构化请求响应模型和稳定错误映射。
- 近期行情获取将复用现有 AkShare 规范化与 `price_history` 缓存，但使用独立于持仓买入日期的分析窗口，不改变现有持仓历史图表语义。
- 设置 API 与本机密钥存储将增加 DeepSeek 配置能力；数据库不持久化 API Key，第一版不要求新增业务表，近期行情继续使用现有 `price_history` 技术缓存。
- 持仓详情页将增加“更新行情并 AI 复盘”入口、分阶段加载状态、结构化结果、数据局限和失败重试体验。
- 后端依赖将增加受控的 HTTP 客户端或等价 DeepSeek API 调用依赖；强制测试仍默认阻断所有真实网络。
- 不包含新闻、财报、行业研究、组合批量 AI 复盘、对话聊天、自动调整止损、自动加减仓或券商下单。
