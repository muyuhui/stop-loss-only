## Why

稳定版 legacy 工作流在功能上已经完整，但若干可见状态会削弱用户信任：未定价持仓以精确的零收益率和零止损距离展示；空组合被报告为行情覆盖率 100%；告警页面还展示不会影响结果的控件。此外，运行时能力已关闭的风险规划仍占据仪表盘和设置页的显著空间，即使用户无法完成该流程。

## What Changes

- **破坏性变更**：在取得符合条件的行情之前，依赖行情的持仓指标改为可空值；前端显示明确的中文未知状态，不再伪造零值。
- 没有活动持仓作为分母时，监控覆盖率返回不可用；存在活动持仓但均未覆盖时，仍保留真实的 0% 覆盖率。
- 移除告警页面中无效的生命周期、风险和排序控件，改为紧凑且稳定的筛选集合；由服务端在分页前执行快照搜索、阅读状态和处置状态筛选。
- 触发告警的持仓被手动关闭时，同步 legacy 告警处置状态，使受支持的处置筛选与已经提交的生命周期事实一致。
- 对应运行时能力不可用时，隐藏仪表盘和设置页的风险预算区域；保留受保护的规划器直达路由，以及能力不可用时默认关闭的行为。
- 补充组件、API 和三个目标视口的回归覆盖，验证未知值、告警筛选及能力感知的区域可见性。

## Capabilities（能力范围）

### New Capabilities（新增能力）

无。

### Modified Capabilities（修改能力）

- `holdings-crud`：在取得可用行情前，依赖行情的收益率和止损距离明确返回不可用。
- `monitoring-diagnostics`：没有活动持仓作为分母时，覆盖率不可用，不再返回 100%。
- `alert-system`：稳定告警视图使用更精简、由服务端支持的筛选契约，并一致记录 legacy 关闭处置状态。
- `dashboard`：从稳定版仪表盘的信息层级中移除能力已关闭的风险预算内容。
- `frontend-shell`：未知的财务/风险值和不可用的可选能力不再以虚假精度或显眼的无出口区域呈现。
- `runtime-settings`：仅当运行时能够在受支持流程中使用风险预算设置时，才显示风险政策控件。
- `quality-gates`：强制测试覆盖修正后的可信语义、实际生效的告警筛选及能力感知的可见性。

## Impact（影响）

- 后端持仓与监控状态的响应模型和展示逻辑将允许派生指标及覆盖率为空。
- 告警列表 API 新增经过校验的快照搜索和稳定处置语义；关闭 legacy 持仓时，在同一业务事务中更新相关待处理告警。
- 仪表盘、持仓列表、持仓详情、告警和设置组件会调整条件渲染及 URL/查询参数行为。
- 冻结的 legacy 响应样例和测试需要有意识地更新；本变更不包含 Position 权限切换、CSV、Webhook、系统通知权限、外部依赖或数据库权限阶段变更。
