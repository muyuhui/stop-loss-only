## Why

当前稳定版能监控止损，却无法回答用户在已经选定标的和风险规则后“最多可以买多少”或“现有持仓最多还能加多少”。仓库虽已有风险预算与新仓数量规划基础，但它被限定在尚未受稳定运行时支持的 Position 权威阶段，导致 legacy/shadow-read 用户无法获得可解释、不会写入业务数据的风险试算。

## What Changes

- 在受支持的 `legacy` 与 `shadow-read` 运行面开放只读风险预算和试算能力，同时继续关闭 Position 创建、加仓、部分平仓及其他生命周期写入。
- 提供新仓买入风险试算：用户明确输入标的、计划价格、费用、止损规则和可选单笔风险比例，系统按组合风险容量计算最大建议数量。
- 在活动 Holding 详情中提供加仓风险试算：使用用户输入的计划成交价和费用，并保留现有止损价，不自动放宽止损或重置移动止损高水位。
- 返回试算前后组合风险、当前持仓风险、增量风险、预计止损损失、所需资金、取整前后数量和稳定拒绝原因；任何风险覆盖不完整或关键输入不可用时不给出建议数量。
- 前端统一使用“风险试算”和“风险约束下的最大数量”文案，明确结果不是标的推荐、收益预测、下单指令或风险额度预留。
- 第一版不判断标的是否值得买，不生成技术/基本面信号，不连接券商，不自动下单，也不修改 Holding、Position、止损规则或交易批次。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `position-sizing-planner`：从仅限新权威 Position 的新仓规划，扩展为受支持稳定运行面可用的只读新仓买入与 Holding 加仓风险试算。
- `risk-budget-management`：按当前权威模型计算覆盖完整且不伪造精度的组合止损风险，使 legacy/shadow-read 可以安全读取风险容量。
- `runtime-capabilities`：在稳定运行面声明风险预算读取和只读风险试算可用，同时继续明确关闭所有 Position 生命周期写入。
- `holdings-crud`：在活动持仓详情增加只读加仓试算入口，并保持原有持仓与止损事实不变。
- `quality-gates`：增加新仓/加仓计算、拒绝路径、零写入保证、能力边界和目标视口交互的强制回归覆盖。

## Impact

- 后端风险预算服务需要按权威阶段读取 legacy Holding 或 Position，并共享 Decimal、覆盖率、费用和数量取整规则。
- 风险 API 将增加 Holding 加仓试算契约；现有新仓预览契约需要解除对 Position 创建能力的耦合，但仍保持只读。
- 运行时能力策略、风险设置可见性、仓位规划页和 Holding 详情页会调整；规划结果不再直接提供未受支持的 Position 创建操作。
- 后端 API/服务测试、真实 Vue 组件测试、三个目标视口 E2E、冻结契约与 README 需要同步更新。
- 不需要数据库模式迁移或外部依赖；不改变现有 Holding、Position、告警、行情或止损写入权限。
