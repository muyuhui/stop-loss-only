## ADDED Requirements

### Requirement: 桌面通知通道
系统 SHALL 在告警提交后通过本地桌面通知（Windows toast）送达止损触发事实，不依赖前端浏览器标签页存活；每次监控周期（调度刷新与手动刷新共用）MUST 最多发送一条汇总通知；通知发送失败 MUST 不影响监控事实与周期结果（post-commit 隔离，仅记录日志）；未启用设置、演示暂停或运行时能力不可用时 MUST 不发送。

#### Scenario: 浏览器关闭时触发仍送达
- **WHEN** 桌面通知已启用且浏览器未打开，监控周期触发止损
- **THEN** 系统在告警提交后发送一条本地桌面通知，内容与内容模式一致

#### Scenario: 每次周期最多一条汇总通知
- **WHEN** 同一监控周期内多笔持仓触发止损
- **THEN** 只发送一条汇总通知，正文包含触发笔数（完整模式最多列出前 3 笔）

#### Scenario: 手动刷新触发同样送达
- **WHEN** 用户手动刷新价格且触发止损
- **THEN** 与调度刷新走同一通知钩子，发送汇总通知

#### Scenario: 通知失败不影响周期
- **WHEN** 通知发送抛出异常
- **THEN** 周期状态与告警事实不变，仅记录失败日志

#### Scenario: 未启用或能力不可用不发送
- **WHEN** 桌面通知未启用、处于演示暂停，或运行时能力 `desktop_notifications` 不可用
- **THEN** 系统不发送任何通知且不产生副作用

### Requirement: 通知内容模式与演示暂停
系统 SHALL 支持 `full` 与 `redacted` 两种内容模式及演示暂停：`full` 通知包含持仓名称、代码与价格；`redacted` 通知 MUST 不包含任何持仓信息（名称、代码、价格）且不出现"止损"字样，仅使用通用文案与触发笔数；演示暂停时 MUST 完全静音。模式与暂停状态 MUST 由后端持久化设置控制（通知由后端发送，不得存于浏览器 localStorage）。

#### Scenario: 完整模式包含持仓信息
- **WHEN** 内容模式为 `full` 且触发止损
- **THEN** 通知包含持仓名称、代码与触发时价格

#### Scenario: 脱敏模式零持仓信息
- **WHEN** 内容模式为 `redacted` 且触发止损
- **THEN** 通知只含通用文案与笔数（如"提醒：有 N 笔触发待处理"），不含任何名称、代码、价格或"止损"字样

#### Scenario: 演示暂停完全静音
- **WHEN** 演示暂停开启
- **THEN** 触发止损时不发送任何通知

#### Scenario: 模式切换即时生效
- **WHEN** 用户切换内容模式或暂停状态后发生触发
- **THEN** 通知按新设置发送，无需重启
