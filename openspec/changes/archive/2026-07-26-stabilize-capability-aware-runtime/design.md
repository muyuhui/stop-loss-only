## Context（背景）

系统目前存在两套分别经过测试、但在实际运行时未被一致表达的权威阶段规则。稳定应用只接受 `legacy` 和 `shadow-read`，风险预算与仓位规划接口却要求 `new-authoritative`，而前端始终展示并轮询规划功能。因此，健康的旧版运行时会产生预期内的 409 和通用错误提示；手动切换到新权威阶段的数据库又无法通过就绪检查。

监控展示也存在类似偏差：即使权威交易日历表明市场休市，系统仍会根据上次可操作行情距当前时间的间隔判断过期。恢复流程虽然可以回滚，但成功后会遗留目标目录中的 `.restore.tmp` 数据库。

本变更涉及多个模块，但明确不完成 Position 权威切换，只把当前实际支持的边界变得明确、安全且一致。

## Goals / Non-Goals（目标与非目标）

**目标：**

- 建立一套后端权威策略和一个类型明确的运行时能力响应。
- 让前端可选功能安全降级，同时不影响健康的旧版核心流程。
- 正确表达休市监控以及两种不同含义的行情覆盖率。
- 确保恢复流程不遗留敏感工作数据库。
- 增加贯穿就绪检查、路由、前端、监控和恢复流程的测试。

**非目标：**

- 启用 `new-authoritative` 就绪状态或切换命令。
- 将监控、仪表盘、告警或历史数据迁移到 Position 权威。
- 修改财务计算公式、数据库结构、行情源选择或轮询间隔。
- 启用 CSV、Webhook、浏览器通知、保留策略或通用 Position 生命周期写入。

## Decisions（设计决策）

### 1. 使用类型明确的运行时能力接口

新增 `GET /api/runtime/capabilities`，返回当前权威阶段、该阶段是否受稳定运行时支持，以及固定结构的能力映射。响应由一套后端策略生成，就绪检查和路由守卫也复用该策略。

不再依赖 409 响应推断能力，因为试探请求会产生噪声日志和提示；也不把阶段判断硬编码在前端，避免后续后端规则变化造成漂移。

### 2. 前端可选功能默认关闭

增加轻量的运行时能力状态，在应用启动时加载。只有能力被明确声明为 `true` 时，才启用对应导航和请求。能力发现暂时失败时，稳定的旧版页面仍可独立加载。

能力不可用时隐藏规划器导航。直接访问 `/planner` 时展示不可用说明，而不是静默跳转，以保留书签语义并解释当前边界。仪表盘保留精简的风险预算不可用区域，但不会请求 `/risk/budget`。

### 3. 对预期内的能力冲突进行局部处理

扩展 API 请求策略，允许调用方显式标记或抑制预期内的能力错误。拦截器继续展示意外错误，能力状态和受保护视图则自行呈现稳定的不可用原因。

不全局忽略所有 409，因为刷新竞争、乐观并发和校验冲突仍然需要用户关注。

### 4. 增加交易日历感知的新鲜度状态并保持兼容

监控状态新增 `healthy`、`overdue`、`market_closed`、`no_success` 等新鲜度枚举，并分别提供可操作覆盖率和估值覆盖率。保留 `overdue` 和 `quote_coverage_pct` 作为兼容字段。

当最近一次权威调度周期因 `market_closed` 跳过时，返回 `market_closed` 且 `overdue=false`，同时继续展示上次成功行情时间。重新进入应有可操作行情的时段后，再恢复常规过期判断。估值覆盖率独立统计可供展示的保留价格，不受 `is_actionable` 限制。

### 5. 在保证执行的收尾路径中清理恢复工作文件

保留现有“复制并校验”流程和固定恢复点，但在 `finally` 收尾路径中删除目标目录内的工作副本，无论成功或失败都执行。清理失败时返回明确的运维错误，且绝不删除活动数据库或恢复点。

不自动删除 `*.recovery.db`，因为它是用户的回滚资产，而不是实现细节产生的临时文件。

### 6. 测试组合后的真实运行时

增加使用真实应用工厂和生命周期的后端集成测试、使用真实能力状态和错误策略的前端挂载测试、确定性的交易日历测试，以及验证文件系统后置条件的恢复测试。浏览器 E2E 聚焦稳定运行时支持的流程，并验证不可用命令无法触达。

## Risks / Trade-offs（风险与权衡）

- 运行时能力响应会成为新的启动依赖：可选功能默认关闭，核心页面请求保持独立。
- 隐藏规划器导航可能让曾经见过该入口的用户困惑：仪表盘和直接路由保留明确说明。
- 休市状态可能掩盖过旧行情：继续展示 `last_success_at` 和估值价格年龄，只在权威休市期间抑制运维过期告警。
- 兼容字段会暂时延续旧术语：将其记录为别名，并立即让前端改用含义明确的新字段。
- 恢复成功但临时文件清理失败时，命令状态可能不够直观：返回独立的清理错误，同时保留活动数据库和恢复点，不在敏感工作文件仍存在时宣称完全成功。

## Migration Plan（迁移计划）

1. 增加统一能力策略、响应模型和只读接口，暂不改变现有守卫行为。
2. 增加前端能力启动状态，将仪表盘和规划器改为遵循新契约。
3. 扩展监控响应字段并迁移前端展示，同时保留旧字段。
4. 增加恢复流程收尾清理和文件系统断言。
5. 连续两次运行后端、前端、构建、浏览器 E2E、冒烟、恢复演练和严格 OpenSpec 校验。

回滚只涉及代码：撤销能力接口、前端和监控修改即可。恢复清理不改变数据库格式，已有恢复点仍可使用。

## Open Questions（待确认事项）

- 未来若重点转向功能可发现性，不可用导航应该继续隐藏还是改为禁用状态。本提案暂时选择“隐藏导航，同时在仪表盘和直接路由中解释原因”。
